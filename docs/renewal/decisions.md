# リニューアルの決定記録

サイトのリニューアル（UI/UX・ワークフロー・設計の作り直し）で決めたことを、日付と理由つきで残す。新しく決めたら末尾に追記し、過去の決定を変えるときは消さずに「変更」として書き足す。

## 進め方（2026-11-19 承認）

新しい骨組みを現行コードと同じ `main` の中で共存させ、役割の単位で 3 回に分けて本番に出す。

| 段階 | 中身 |
|---|---|
| Phase 0 | 土台と安全確保。0-1 テスト環境の隔離 / 0-2 出発点の固定 / 0-3 計算結果の記録 / 0-4 CI / 0-5 本番の確認とバックアップ / 0-6 ファイル台帳 / 0-7 `CLAUDE.md` の移行期対応 |
| リリース① | 新しい骨組み（ログイン部分）と、現行の管理ページへの主催者ログイン必須化 |
| リリース② | 公開ページ一式・トップページ・参加者ページを新デザインで入れ替え。旧 URL からの転送 |
| リリース③ | 主催者の運営画面を入れ替え、旧コードを撤去 |
| 後片付け | リリース③の様子見の後に、制約の追加・設定の保存形式の移行・不要列の削除 |

守ること:

- リリース③までは DB の保存形式を変えない（旧版へ戻せなくなるため）。CHECK 制約・NOT NULL の追加、列の転用、`tournament_meta` からの移行は後片付けで行う。
- 主キーの値と、Discord に投稿済みの URL は生かす。
- 完了済み大会の敗退回戦は再計算しない。
- 計算結果（順位・合計・分析値）は新旧で突き合わせる。差は、期待値つきで登録しオーナーが承認したものだけ認める。
- 作業の主張には証拠（CI の実行、テスト ID、実行結果）を付ける。確かめていないものは「未確認」と書く。
